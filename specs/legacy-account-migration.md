# 기존 메인 계정 → 새 로그인 계정 이전 준비

2026-10-29 · 준비 단계. 실제 계정·로그인·서버 저장 구조는 변경하지 않았다.

## 확인한 현재 구조

메인 계정은 브라우저 localStorage의 `skullCreekAccounts` 계정 목록과 `skullCreekAccount`, sessionStorage의 `skullCreekActiveAccountId`를 사용한다. 새 베타 로그인은 서버 인증 계정과 SQLite 저장이다. 같은 아이디·닉네임만으로 소유자를 연결할 수 없다. 브라우저의 사이트 주소·포트가 달라지면 별도 저장소이므로 원래 접속 주소에서 내보내야 한다.

## 이전 절차

1. 원래 메인 주소의 로그인된 계정과 목록을 확인한다. 계정이 여러 개라면 대상 하나를 명시적으로 선택하고 나머지는 보존한다. 계정 목록·활성 저장이 서로 다르면 자동 선택하지 않는다.
2. 기존 계정 내보내기 형식 `colors-account` 버전 1로 원본 파일을 보관한다. 서버 DB 백업도 따로 만든다. 이전 작업 중 플레이·재화 변경을 멈추고 여러 탭의 저장을 확인한다.
3. 새 계정을 생성하거나 로그인한다. 비밀번호·로그인 세션은 새 인증 서버에서 관리한다. 기존 로컬 ID는 과거 식별자로 보관한다.
4. 코인·크레딧·캐릭터·스킨·레벨·트로피·모드/시즌별 전적·일일 진행·꾸미기·장착을 이전 미리보기로 표시한다. 알려지지 않은 저장 항목도 원본 스냅샷에 보존한다.
5. 새 계정에 이미 진행도가 있으면 덮어쓰기·합산을 중단하고 별도 충돌 처리한다. 베타 시험 재화를 메인 재화에 더하지 않는다. 기존 전적은 과거 기록으로 보존하되 새 경쟁 랭킹에 검증된 경기처럼 소급 합산하지 않는다.
6. 서버에서 대상 로그인 세션·원본 소유 확인 정책·저장 버전·원본 변경 여부를 다시 검사한다. 동일 원본에 대한 이전 권한과 완료 기록을 트랜잭션으로 한 번만 반영한다. 동일 이전 재시도는 기존 결과를 반환하고 다른 계정의 중복 인수는 거절한다.
7. 서버가 원본 해시·대상 계정·반영 버전·이전 작업 ID를 포함한 완료 기록을 반환한다. 새 로그인으로 재접속해 원본과 모든 항목을 대조한다.
8. 검증 후 새 저장을 사용하도록 연결하되 원본 내보내기·기존 브라우저 저장은 보관한다. 실패·네트워크 중단·충돌이면 이전 완료로 표시하지 않는다. 실제 적용은 이 절차와 통합 시험을 통과한 뒤 진행한다.

## 준비·검증 완료

`tools/plan-legacy-account-migration.mjs`는 게임이나 서버에 연결되지 않은 오프라인 계획기다. 기존 계정 파일 파서를 사용하고 전체 스냅샷과 비교용 해시, 원본 단위 중복 방지 식별자, 대상 예상 버전을 준비한다. 해시는 인증 수단이 아니다.

`node tools/test-legacy-account-migration.mjs`로 시험 데이터 검증 9항목 통과: 전체 항목·알 수 없는 중첩 항목 보존, 입력 원본 유지, 반복 계획 안정성, 키 순서와 무관한 해시, 잔액 변경을 통한 새 이전 식별자 생성 방지, 대상 충돌 거절, 잘못된 입력 거절, 완료 기록 불일치·원본 변경 감지, 원본 삭제 금지.

## 적용 전에 남은 작업

- 기존 로컬 계정 소유 확인 정책: 로컬 ID·닉네임·파일만으로 전 세계에서 단독 소유권을 증명할 수 없다. 공개 자동 이전의 신뢰 범위를 정해야 한다.
- 실제 서버의 원자적 이전 API·대상/원본 중복 차단·완료 기록 구현.
- 메인·베타 저장 형식을 하나의 공용 진행도에 연결하는 변환기 구현. 스냅샷 보존만으로 게임에서 사용할 수 있는 이전이 끝난 것은 아니다.
- 별도 DB와 Ego에서 이전 성공·재시도·동시 요청·중간 실패·재로그인 보존 검증.

이번 검증은 준비용 계획기와 시험 데이터에 한정된다. 실제 서버 이전이나 실제 사용자 진행도 이전 완료를 뜻하지 않는다.
