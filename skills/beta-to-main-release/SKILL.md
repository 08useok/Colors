# 베타 업데이트 메인 이식

프로젝트의 AGENTS.md를 먼저 읽는다. 요청한 시즌과 범위가 명확하면 진행하고, 전체 시즌인지 밸런스만인지 판단할 수 없으면 한 번 확인한다.

## 원본과 범위

- `src/beta-season.js`, `src/config/beta-characters.js`, 해당 시즌 balance 모듈에서 실제 활성 콘텐츠를 확인한다.
- `specs`의 후보 비교 JSON은 출시된 값이 아니다. `applied:false` 후보와 미래 시즌 기능을 자동 적용하지 않는다.
- 메인 진입점은 `index.html` → `src/main.js`다. 스펙·설명·설정만 변경하고 이식이 완료됐다고 보고하지 않는다.
- 전체 시즌 요청이면 캐릭터/궁극기/기본 공격, 밸런스, 봇 전용 조정, 스킨/걷기 모델, 테마/음악, 맵/정규 모드, 상점/계정 저장/공지까지 원본과 메인 연결을 표로 기록한다.

## 구현 주의점

- 두 런타임의 좌표축, 시간 기준, 레벨 피해 배율, HP/사망/리스폰, 팀과 네트워크 판정이 다르다. 공통 모듈을 재사용할 때 변환을 확인한다. 피해 배율·가드·충전을 두 번 적용하지 않는다.
- 봇 전용 회피·조준·궁 사용 체력 조건을 플레이어 조작에 적용하지 않는다.
- FBX 구체 같은 프리뷰 메시는 크기 계산 전에 제외하고 실제 파일의 축을 확인한다. 스킨 경로와 기본 캐릭터 경로를 분리하고 늦게 완료된 로딩이 이전 선택/종료된 전투에 적용되지 않게 한다.
- 전투/모드 종료 시 투사체, 장판, 모델, 장치, 전선, 분석 속박과 비동기 상태를 정리한다.
- 계정의 기존 보유 캐릭터·스킨·재화·진행도를 보존한다. 신종은 구매/선택/통계/레벨/HUD 모두 연결한다.
- 캐시 버전을 바꿀 때 실제 메인 HTML과 하위 import를 함께 확인한다.

## 검증과 보고

변경된 연결과 전투 의미를 검증하는 기존 검사를 실행한다. 필요한 경우 누락·이중 피해·수동 조작·리스폰·종료 후 잔여 객체의 회귀 검사를 추가한다. 프로젝트에 지정된 브라우저 도구가 없으면 사용 가능한 브라우저 도구를 확인하고, 화면 검증을 못 했을 때는 그 한계를 보고한다.

시뮬레이션은 게임 화면 검증과 구분한다. 전체 상성 재실행은 전투 규칙이나 봇 동작이 바뀐 경우 수행하며 기존 지정 상성의 회귀를 확인한다. 의도한 100%/0%와 다른 극단 승률은 같은 목표로 취급하지 않는다.

최종 보고에는 이식한 범위, 검증 결과, 남은 차이를 적는다. 커밋·푸시·배포는 별도 요청에 따른다. 커밋·푸시 요청 시 `commit-and-push` 스킬을 사용한다.
